# 2026-07-22 工作日志

## 智能导入工具：勾选框默认值调整 + 命名冲突崩溃修复

### 默认值调整
- `bUseCombinedNamePrefixCheckbox`（拆分模型添加合并模型名前缀）默认改为 Unchecked
- `Widgets.bUsePrefix`（前缀勾选框，Mesh/Texture/Material/Instance 全部）默认改为 Unchecked

### 崩溃根因分析
取消所有前缀后，不同类型资产在同一目录下名称冲突：
- 模型从 FBX 导入为 "Chair"（无前缀）
- 材质从 "Chair_BaseColor" 贴图名剥离后缀得到 "Chair"
- `AT.CreateAsset("Chair", FinalPath, UMaterial, ...)` 覆写了已存在的 StaticMesh "Chair"
- 原 StaticMesh 对象被销毁，但 Meshes 数组仍持有悬垂指针 → ApplyMaterialsToMeshes 崩溃

### 修复方案
1. 新增 `DoesAssetExistInPath` — 用 `FindObject<UObject>` + 资产注册表双重检查同名资产是否存在
2. 新增 `MakeUniqueAssetName` — 名称冲突时自动追加 _1, _2... 消歧
3. 新增 `CollectAllStaticMeshesInPath` — 重命名后按路径收集所有 StaticMesh（不按名过滤）
4. 所有 `AT.CreateAsset` / `AT.DuplicateAsset` 调用前加 `MakeUniqueAssetName`（4 处材质创建 + 2 处实例创建）
5. `RenameSplitMeshes` 改用 `AT.RenameAssets`（非对话框），并在消歧循环中加入 `DoesAssetExistInPath` 检查
6. 重命名后用 `CollectAllStaticMeshesInPath` 重新收集（原 CollectImportedMeshes 按名过滤会漏掉改名后的子模型）
7. `ApplyMaterialsToMeshes` 加入 `IsValid(SM)` 和 `IsValid(MatPair.Value)` 防御性检查
