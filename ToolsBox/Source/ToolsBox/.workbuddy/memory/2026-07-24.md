# 2026-07-24 工作日志

## 修复 AssetAction.cpp 编译错误

### 问题根因
`AssetAction.h` 第 5 行 `#include <AclAPI.h>` 拉入 `windows.h`，其定义的宏破坏了引擎 Chaos 头文件：
- `min`/`max` 宏 → 破坏 `std::numeric_limits<T>::max()` / `::min()`（C4003/C2589/C2760）
- `GetObject` → `GetObjectW` 宏 → 破坏 `Chaos::FImplicitObject::GetObject<T>()`（C2039）

### 修复内容
1. **`Public/Tools/Right-ClickOperationTool/AssetAction.h`**
   - 移除 `#include <AclAPI.h>`（代码中未使用任何 ACL API）
   
2. **`ToolsBox.Build.cs`**
   - PrivateDependencyModuleNames 新增 3 个缺失模块：
     - `PhysicsCore`（UPhysicalMaterial）
     - `BlueprintGraph`（UK2Node_EditablePinBase）
     - `StaticMeshEditor`（UStaticMeshEditorSubsystem）
   - 这些链接错误之前被编译错误掩盖，编译修复后暴露出来

### 经验教训
- UE 插件头文件中**绝不要**直接 `#include <windows.h>` 或其他 Win SDK 头文件
- `NOMINMAX` 只解决 `min`/`max`，还有 `GetObject`、`DeleteObject`、`CreateWindow` 等无数宏会破坏引擎代码
- 正确做法：不需要就不用；需要的话放 .cpp 里，在引擎头文件之后 include
