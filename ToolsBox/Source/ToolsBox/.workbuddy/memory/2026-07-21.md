## ORM贴图导入问题修复

### 问题
导入工具在遇到ORM贴图（AO/粗糙度/金属度三合一）时处理不正确：
- ORM贴图被当做AO贴图处理
- MIC模式下Use_ORM开关为false（应为true）
- AO默认启用且ORM贴图被放入AO参数

### 解决方案（按用户思路重构）
将 `GenerateMaterials` 中的材质生成逻辑按有无ORM贴图拆分为两个独立函数：

1. **GenerateMaterialWithoutORM** — 无ORM贴图时的材质生成（原有能正常工作的逻辑）
   - MIC模式：Use_ORM=false，根据有无AO/R/M贴图分别设置Use_AO/Use_Roughness/Use_Metallic
   - 母材质模式：各贴图分别连接到对应材质属性引脚

2. **GenerateMaterialWithORM** — 有ORM贴图时的材质生成（新写）
   - MIC模式：Use_ORM=true，Use_AO/Use_Roughness/Use_Metallic=false，ORM贴图放入ORM参数
   - 母材质模式：ORM贴图R/G/B通道分别连接到AO/Roughness/Metallic引脚

3. **GenerateMaterials** 中通过 `LocalMatch.Contains(TEXT("ORM"))` 判断分发

### 修改文件
- `Public/Tools/IntelligentImportOfModelsAndMaterials/Import_MM.h` — 添加两个函数声明
- `Private/Tools/IntelligentImportOfModelsAndMaterials/Import_MM.cpp` — 替换分支代码为分发逻辑，新增两个函数实现

### 追加修复：ORM贴图匹配条件缺陷（18:29）

**根因**：纹理分类阶段（GenerateMaterials 的 else if 链）中，ORM检测条件只匹配 `"orm"` 子串，但引擎常用的 ORM 纹理命名为 `*_OcclusionRoughnessMetallic.*`，小写后不包含 `"orm"` 子串，导致落到 AO 检测条件（包含 `"occlusion"`），被错误分类为 AO 贴图。

**修复**：将 ORM 匹配条件从 `L.Contains(TEXT("orm"))` 扩展为：
```cpp
L.Contains(TEXT("orm")) || (L.Contains(TEXT("occlusion")) && L.Contains(TEXT("roughness")) && L.Contains(TEXT("metallic")))
```
同时包含 `*_orm.*` 和 `*_OcclusionRoughnessMetallic.*` 两种常见命名约定，且该检查仍在 AO/Roughness/Metallic 的独立检查之前执行。

### Data.h 重命名 + TextureParam FName 类型修复（19:05）

文件结构调整：`Import_MM_Data.h` 改名为 `Data.h` 并移至 Public 目录。

**错误**：`OnCreateGenericMaterialClicked` 中 CreatePBRChannel 调用报编译错误：
"无法将类型 const FString 的左值转换为形参类型 FName，因为构造函数 FName(TStringView<WIDECHAR> View, EFindName FindType = FNAME_Add) 为显式"

**根因**：Data.h 中 `TextureParam` 定义为 `FString`，但 `CreateChannel` 和 `CreatePBRChannel` 的 lambda 参数都是 `FName`，UE5.8 中 `FName` 的 `TStringView` 构造函数是 `explicit` 的。

**修复**（同步类型，不是逐处 cast）：
- Data.h：`TextureParam::*` 从 `const FString` 改为 `const FName`
- Data.h：`FChannelMeta::DefaultTextureParam` 从 `FString` 改为 `FName`
- Import_MM.cpp：`ApplyTexture` lambda 的 `DefaultParamName` 参数从 `const FString&` 改为 `FName`，内部改用 `.ToString()` 转换

### 三元运算符 TEnumAsByte 类型歧义修复（19:26）

**错误**：`Meta ? Meta->CompressionSettings : TextureCompressionSettings::TC_Default` 报"条件表达式 result 类型有歧义"。

**根因**：`Meta->CompressionSettings` 是 `TEnumAsByte<TextureCompressionSettings>`，`TC_Default` 是原始枚举 `TextureCompressionSettings`，三元运算符无法推导公共类型（`TEnumAsByte` 双向隐式转换导致歧义）。

**修复**：true 分支显式 cast 为原始枚举 — `Meta ? (TextureCompressionSettings)Meta->CompressionSettings : TC_Default`，两处 ApplyTexture lambda 均改。
