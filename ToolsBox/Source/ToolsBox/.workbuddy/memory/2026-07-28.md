## 材质属性转移工具新增"保存到各自文件夹中"勾选框

### 需求

勾选时，筛选并选中多个不同文件夹下的材质实例，转换生成的新 MIC 各自保存回源材质所在文件夹，而非统一存到同一路径。

### 改动文件
- **`Public/Tools/MaterialTttributeTransfer/MaterialTttributeTransfer.h`**
  - 新增成员 `bool bSaveToRespectiveFolders = true;`（默认勾选）
- **`Private/Tools/MaterialAttributeTransfer/MaterialAttributeTransfer.cpp`**
  - 新增 `#include "Widgets/Input/SCheckBox.h"`
  - "生成保存路径"区块改为 SVerticalBox：第一行路径输入+获取路径按钮（均加 `.IsEnabled_Lambda([this](){ return !bSaveToRespectiveFolders; })`）；第二行新增 SCheckBox 开关 + 说明文字
  - `OnExecuteTransfer` 重写路径逻辑：原"一次性算 FinalPath"改为循环内按模式计算。勾选 → `FinalPath = FPaths::GetPath(SourceMat->GetPathName())`（源材质包路径）；未勾选 → 沿用旧的统一路径清理逻辑

  - 成功日志改为 `成功生成: %s -> %s`（资产名 + 目标路径）
  - 配置存取：`SaveSettings` 写入 `SaveToRespectiveFolders` 布尔；`LoadSettings` 读取（HasField 保护，缺省保持默认 true）

### 注意
- 头文件名是 `MaterialTttributeTransfer.h`（有拼写 Tttribute），.cpp 在 `MaterialAttributeTransfer/`，路径拼写不一致，引用时注意
- `FPaths::GetPath(SourceMat->GetPathName())` 对顶层资产返回 `/Game/路径`（去掉了 `.资产名` 后缀），可直接作 CreateAsset 的 PackagePath

### 编译中顺手修的两个错误（非本次需求，但阻断编译）
- `SlateAssistBuildFunctionLibrary.cpp` 误写 `"Widgets/Layout/SOverlay.h"` → 正确路径是 `"Widgets/SOverlay.h"`
- `Import_MM.cpp:191` 误用 `.ToolTip(LOCTEXT(...))`（STextBlock 的 ToolTip 接收 `TSharedPtr<IToolTip>`，不是 FText）→ 改为 `.ToolTipText(...)`。这是用户近期改文件引入的，与本次需求无关。

### 经验教训
- `SBox.h` 在 `Widgets/Layout/`，但 `SOverlay.h` 在 `Widgets/`（SlateCore 模块，无 Layout 子目录），include 路径别搞混
- Slate 控件 `.ToolTip(对象)` vs `.ToolTipText(文本)` 是两个不同重载，传文本必须用后者
- 引擎可用图标 brush：`Icons.Link`（链接）、`Icons.Help`、`Icons.Launch`、`Icons.Info`（均已确认存在于 SlateCore）
